# オーラコネクト・バトル

オーラ(玉)をつないで消し、仲間と共にダンジョンを攻略するブラウザ/PWA のパズルRPG。
ビルド不要の静的サイトで、ES Modules をそのまま読み込んでいる。

## ディレクトリ構成

```
.
├── index.html              画面の骨組み(DOM)のみ。ロジックは持たない
├── manifest.json           PWA マニフェスト
├── sw.js                   Service Worker(アプリ本体は network-first)
├── assets/
│   ├── icons/              アプリアイコン
│   ├── ui/                 メニューアイコンのアトラスとダンジョン背景
│   └── chars/              キャラクターイラスト(置くと自動で使われる)
└── src/
    ├── css/style.css       全画面のスタイル
    └── js/
        ├── main.js         エントリポイント。初期化と画面登録
        ├── core/
        │   ├── storage.js  localStorage ラッパー
        │   ├── state.js    セーブデータ / 編成 / スタミナ / ランク
        │   ├── nav.js      画面遷移とトップバー
        │   ├── sysmodal.js ⚙ システムモーダル(音量・リタイア)
        │   ├── ui.js       toast などの汎用ユーティリティ
        │   ├── firebase.js Firebase SDK の遅延読み込み
        │   └── friends.js  フレンド機能とクラウド保存
        ├── data/
        │   ├── characters.js オーラ / キャラクター / レベル・進化 / NPCサポート
        │   ├── skills.js     リーダースキル / スキル / 進化時の強化規則
        │   └── gamedata.js   ステージ・素材・ショップ・ガチャ・各種定数
        ├── battle/
        │   ├── board.js    盤面データ操作(生成 / 連結判定 / 落下 / 補充 / 変換)

        │   ├── renderer.js Canvas 描画
```

依存の向きは `screens・battle → core → data` の一方向。
`nav.js` は画面の描画関数を `registerScreen()` で受け取るだけなので、
画面モジュールと相互参照しない。

## ゲームの主なルール

### 編成は「人物」4人
自陣は**人物キャラクター3人**(先頭がリーダー)と、ダンジョン出発時に選ぶ
**サポート1人**の計4人。サポートはフレンドの貸し出しキャラに加えて、
**NPCサポート**をいつでも選べる(フレンドがいなくても困らない)。
NPCサポートはプレイヤーランクで順次解放される。

### オーラ
オーラは4色。🔥火 / 💧水 / 🌿木 / 💗癒。癒は攻撃ではなく**回復**を担当する。
盤面は7列×8行、同じオーラが**4つ以上**つながると消滅する。

### レアリティ・レベル・進化
- ガチャで出るのは **★1〜★4(N / R / SR / SSR)**。**★5(UR)は進化でのみ到達する**。
- キャラクターはレベルを持ち、ダンジョンクリアで編成キャラに経験値が入る。
  レベル上限はレアリティごと(★1:15 / ★2:20 / ★3:30 / ★4:40 / ★5:60)。
- **進化はキャラクターごとに1段階だけ**(★1→★2、★3→★4、★4→★5)。
  つまり **★5(UR)に到達できるのは★4のキャラクターだけ**で、レアリティの価値は保たれる。
- **進化**にはレベル上限到達 + 素材 + コインが必要。ダンジョンで
  オーラ別の結晶(紅蓮/蒼海/翠緑/聖光)と**進化の輝石**が手に入る。
- 進化するとステータスが伸びるだけでなく、**リーダースキルとスキルも強化**される
  (専用の強化版が無いキャラは `skills.js` の規則で自動的に強化される)。
- **レベルと進化でイラストが変わる**。`assets/chars/` に画像を置くと使われ、
  無い場合は絵文字で表示される(詳しくは `assets/chars/README.md`)。

### 画像まわりの決めごと
- 画像はすべて **WebP**。PNG原本は `_original/` に置き `.gitignore` で除外する。
- ホームのメニューアイコンは **1枚のアトラス**(`assets/ui/menu_atlas.webp`、
  256px × 4列2行)にまとめ、CSSの `background-position` で切り出している。
  8枚を個別に置くとリクエストが8回になるため。並び順は style.css の
  `.t-*  .tile-icon` を参照。
- ダンジョン背景は `body.in-battle.boss-floor #app::before` に敷き、上から暗幕を
  重ねてUIの可読性を保っている。表示するのは最終フロア(ボス)のときだけ。
- アプリアイコンは `any` と `maskable` を分けて用意している。maskable は中央80%の
  円が安全領域で、その外は切り落とされるため、装飾の金枠を除いて絵が端まで届く版を
  別途置いている(`icon-maskable-*.png`)。同じ画像を使い回すと枠が中途半端に切れる。

### 開眼
- **同じキャラクターを重ねて行う強化**。最大4段階で、段階ごとに別々の効果が付く。
  1段階につき手持ちの同キャラを**1体消費**する(消費するので手持ちが2体以上必要)。
- 効果の内容は `src/js/data/characters.js` の `AWAKEN_BY_ROLE`(ロール既定)と
  `AWAKEN_BY_ID`(キャラ個別)で決まる。操作時間延長 / スキルのCT短縮 /
  ATK・HP・RCVアップ の4種類。
- 反映は `resolveCharacter()` に集約している。ATK・HP・RCV とスキルCTはそこで
  適用し、操作時間だけはパーティ単位なので `battle/party.js` が合算する。
- **フレンドから借りたサポートキャラにも反映される。** 貸し出し情報として
  `rentalAwa` を `users/{uid}` に持たせ、クラウド保存のたびにレベルと合わせて
  最新へ同期している(貸し出し設定後に育てても古い値が残らない)。
- ガチャの被りはこの素材になる(それまで所持数は数えるだけで使い道が無かった)。

### 看板キャラクター「カイ」
水オーラの★4アタッカー。ガチャのピックアップ対象。

| | ★4 | ★5(進化後) |
| --- | --- | --- |
| 二つ名 | 虚空の剣士 | 虚空を断つ者 |
| リーダースキル | 不器用な誓い<br>操作時間+3.0秒・水オーラ1.8倍・被ダメージ15%減 | 虚空剣の誓約<br>操作時間+5.0秒・水オーラ2.6倍・全オーラ1.2倍・被ダメージ25%減・最大HP1.2倍 |
| スキル | 不完全な斬撃(CT11)<br>火と木を水に変化・操作時間+3.0秒 | 虚空斬・完全(CT9)<br>火と木を水に変化・攻撃力×8のダメージ・操作時間+5.0秒 |

### キャラクターごとの攻撃
- 各キャラクターは固有のオーラを持つ。
- **自分のオーラを消したときだけ攻撃する**。消さなかったキャラは攻撃しない。
- 消した数が多いほど、そのキャラの攻撃力が上がる。
- 癒オーラのキャラは攻撃のかわりにパーティを回復する。
- 編成した4人がそれぞれ個別に敵を攻撃する(ダメージもキャラごとに表示)。

### 操作時間は10秒
最初にオーブへ触れてから**10秒**。指を離しても時間内なら何度でも掴み直せる。
時間が切れると自動的に手番が確定する。この10秒を**リーダースキルとスキルで
延ばして戦う**のが戦術の中心になる(上限40秒)。

### リーダースキル
発動するのは**自陣リーダー(編成1人目)**と**サポート**の2つ。
効果は `src/js/data/skills.js` に定義していて、次の種類がある。

| 効果 | 例 |
| --- | --- |
| オーラ別の攻撃倍率 | 業火の覇者「火オーラ2.2倍・操作時間+2.0秒」 |
| 全オーラの攻撃倍率 | 大聖女の福音「全オーラ1.4倍・回復2.0倍・操作時間+2.0秒」 |
| 操作時間の延長 | 氷結の思考「オーラ操作時間+3.0秒」 |
| 最大HP / 回復力 | 聖騎士の盾「最大HP1.5倍・被ダメージ15%減」 |
| コンボ条件 | 風読みの極意「5コンボ目以降の攻撃力1.8倍」 |
| 連結条件の緩和 | 世界樹の恵み「連結3個で消えるようになる」 |

### スキル
バトル中に仲間をタップして発動。ターン経過でチャージされる(CT)。
操作時間の延長、回復、固定ダメージ、オーラ変換、盤面シャッフル、
攻撃力アップ、被ダメージ軽減、敵の攻撃遅延などがある。

### ガチャ
- **オーブ召喚**(最高 SSR / ピックアップ開催)と**フレポ召喚**(N〜SR中心)の2種類。
- 単発と**10連**があり、10連は1回ぶんお得＆**★3以上が1体確定**。
- オーブ召喚の★4は12%。そのうち `PICKUP_RATE`(現在30%)がピックアップ枠で、
  残りを**ピックアップを除く**★4で均等に分ける(1体あたり約0.76%)。
  ピックアップを通常枠にも残すと表示より出やすくなるため除外している。
- 召喚演出は「魔法陣 → オーラのオーブが集まる → 溜め → フラッシュ → カード出現」。
  集まるオーブの色が期待度を示す(青=通常 / 金=SR以上 / 虹=SSR確定)。画面タップでスキップできる。

### ダンジョン / スタミナ / ランク
- ダンジョンは**ノーマル**と**曜日**の2種類。
- **ノーマルは全10章 × 5ステージ(計50)**。ステージIDは通し番号で、
  章の最終ステージをノーマルでクリアすると次の章が解禁される。
  奥へ進むほど結晶のドロップ量・コイン・キャラ経験値が増える。
- **曜日ダンジョン**は日替わりで手に入るものが変わる。初級/中級/上級の
  3段階があり、プレイヤーランクで解放される。

  | 曜日 | 内容 |
  | --- | --- |
  | 月 | 🩷 聖光の結晶(回復キャラの進化素材) |
  | 火 | 🔴 紅蓮の結晶 |
  | 水 | 🔵 蒼海の結晶 |
  | 木 | 🟢 翠緑の結晶 |
  | 金 | 💰 ゴールド特化(素材は落ちない) |
  | 土日 | 📗 キャラクター経験値アイテム |

- 1ステージ5フロア。フロアは**自動で進み**、フロア間の回復はない。
- 敵は一定ターンごとに攻撃してくる(ボスは毎ターン)。
- クリアすると進化素材がドロップする。ステージごとに主に落ちる結晶のオーラが違う。
- スタミナは3分で1回復。初期ダンジョンの消費は5。
- ステージクリアで EXP を獲得。**ランクアップ時は「現在のスタミナ +
  ランクアップ後の最大スタミナ」になる**ので、スタミナは最大値を超えて
  オーバーフローする(超過ぶんは自然回復では減らない)。

## 開発

ES Modules を使うため `file://` では動かない。ローカルでは HTTP で配信する。

```sh
python3 -m http.server 8000
# → http://localhost:8000/index.html
```

セーブデータは `localStorage` の `acb_state` キー(現行 `version: 6`)。
旧フォーマットは起動時に自動で移行される。
- v4以前(5属性 / モンスター編成): 同じオーラ・レアリティの人物キャラクターへ読み替え、
  旧 光/闇 は癒(ピンク)へ集約される。
- v5(所持数のみ): `{n, star, lv, xp}` 形式へ変換される。

## フレンド機能 / クラウド保存(Firebase)

Firebase は**設定済みのときだけ**動的 import で読み込むため、未設定でも
オフラインでもゲーム本体(ローカル保存)はそのまま遊べる。

`src/js/core/firebase.js` の `firebaseConfig` を、ご自身の Firebase プロジェクトの
設定値に置き換えると有効になる。

**すべて無料枠(Spark プラン)の範囲で動く構成にしている。** Cloud Functions は
Blaze プラン(従量課金)が必須なので使っていない。したがってサーバーサイドでの
検証は行えず、防御は Firestore のセキュリティルールだけが担っている。

### セットアップ手順

1. Firebase コンソールでプロジェクトを作成
2. Authentication → Sign-in method で **「匿名」と「メール/パスワード」の両方**を有効化
3. Firestore Database を作成
   - **本番環境モード**で開始する(テストモードは30日間だれでも全データを読み書きできる)
   - ロケーションは後から変更できない。国内向けなら `asia-northeast1`(東京)
4. Firestore → ルール に下記を貼り付けて公開
5. `firebaseConfig` にプロジェクトの設定値(apiKey 等)を貼り付け

apiKey はクライアントに埋め込む前提の識別子なので、公開リポジトリに入っていても
問題ない。ただし裏を返すと**実際の防御はセキュリティルールだけ**になるため、
公開前に Google Cloud Console でのAPIキー制限(HTTPリファラー)と App Check の
設定を検討すること。

### セキュリティルール

```
rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {

    function signedIn() { return request.auth != null; }
    function isMe(uid)  { return signedIn() && request.auth.uid == uid; }
    function onlyChanged(keys) {
      return request.resource.data.diff(resource.data).affectedKeys().hasOnly(keys);
    }
    // 他人が加算できるのはフレンド報酬の固定額だけ
    function isFriendReward() {
      return onlyChanged(['pendingFrepo'])
        && request.resource.data.pendingFrepo is int
        && (request.resource.data.pendingFrepo == resource.data.pendingFrepo + 300
         || request.resource.data.pendingFrepo == resource.data.pendingFrepo + 10);
    }

    match /users/{uid} {
      // 名前・アイコン・貸し出しキャラはフレンドが読む必要がある
      allow read:   if signedIn();
      allow create: if isMe(uid);
      allow update: if isMe(uid) || (signedIn() && isFriendReward());
      allow delete: if false;

      match /friends/{friendUid} {
        allow read:  if isMe(uid);
        // 自分の一覧は自由に。他人は「自分自身を相手の一覧に追加する」ことだけできる
        allow write: if isMe(uid) || (signedIn() && friendUid == request.auth.uid);
      }

      match /save/{doc} {
        allow read, write: if isMe(uid);   // セーブデータ本体は本人のみ
      }
    }

    match /friendCodes/{code} {
      allow read:   if signedIn();
      allow create: if signedIn() && request.resource.data.uid == request.auth.uid;
      allow update, delete: if false;      // 一度発行したコードの奪取を防ぐ
    }
  }
}
```

このルールで防げるのは「他人のセーブデータの読み書き」「他人のプロフィール改竄」
「フレンドコードの乗っ取り」「任意額のフレポ付与」。

一方、Cloud Functions を使わない以上、**次の2つは防ぎきれない**。
- 自分のセーブデータの改竄(クライアントが書く値をそのまま保存しているため)
- フレンド報酬の連打による稼ぎ(1回あたりの額は固定できるが、回数を制限できない)

いずれも同期型の対人要素が無い現状では実害が小さいため、無料枠を優先して許容している。
ランキング等を入れる場合はここが前提から崩れるので、設計を見直すこと。

### アカウント(ID / パスワード)

メールアドレスは入力させず、IDを実在しないドメイン(`.invalid` は RFC 2606 で
永久に予約済み)のアドレスへ変換して Firebase のメール/パスワード認証に渡している。

```
起動           匿名でサインイン(すぐ遊べる。uid にセーブが紐づく)
  ↓
マイページで登録  linkWithCredential で匿名アカウントを昇格
                → uid が変わらないので、セーブもフレンドも引き継がれる
  ↓
別端末          signInWithEmailAndPassword で同じ uid に戻り、
                クラウドのセーブでその端末を上書きする
```

登録に `createUserWithEmailAndPassword` を使ってはいけない。**新しい uid が
発行され、それまでのセーブが孤児になる。**

ID の重複チェックは Firebase が `auth/email-already-in-use` を返すため、
Firestore 側でユニーク制約を作る必要がない。ただし Authentication の
**Email enumeration protection** を有効にするとエラーが曖昧になり
「そのIDは使用済み」を出せなくなるので、その場合は別途 ID 予約用の
コレクションが必要になる。

**架空アドレスのためパスワード再設定メールは送れない。** 忘れると復旧できない
ことをマイページの登録欄に明示している。

### 管理者アカウント

`src/js/core/account.js` の `ADMIN_IDS` に入れたIDを管理者として扱う。現在は
`cadmium` のみ。

管理者への配布は同ファイルの `ADMIN_GRANTS` に並べる。`key` ごとに一度だけ
適用されるので、追加で配りたくなったら新しい `key` の行を足すだけでよい
(既存の `key` の数値を書き換えても再付与はされない)。現在の合計はオーブ1000。

付与済みフラグは `state.grants` に入り、クラウドセーブにも含めているので、
別端末でログインしても重複して付与されない。

**これはサーバで検証される権限ではない。** Cloud Functions を使わない構成では
クライアントの改変を防げないため、`ADMIN_IDS` は「誰が管理者か」を示す運用上の
目印でしかなく、不正防止の役割は持たない(そもそもローカル保存を書き換えれば
誰でも同じことができる)。管理者に実害のある操作を持たせる場合は、この前提が
成り立たないことに注意すること。

### フレンドでできること
- **プレイヤーアイコンは「フレンドに貸し出しているキャラクター」のアイコン**になる。
  トップバーのアイコンをタップすると所持キャラクター一覧から選び直せる。
  (以前あった絵文字を個別に選ぶ方式は廃止した)
- マイページで発行される「フレンドコード」を交換して友達を登録する
  - フレンド登録時: 自分+300フレポ、相手+300フレポ
  - 毎日1回の「あいさつ」: 自分+20フレポ、相手+10フレポ
- マイページの「貸し出しキャラクター」で1人を指定すると、フレンドの
  ダンジョン挑戦時にサポート枠として借りられる(リーダースキルも発動する)
